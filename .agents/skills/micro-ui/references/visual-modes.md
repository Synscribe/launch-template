# Visual modes

Choose a mode for the communication job, not because it looks fashionable.

| Mode             | Best for                                | Structure                                             |
| ---------------- | --------------------------------------- | ----------------------------------------------------- |
| Decision flow    | Redirects, conversion paths, handoffs   | Distinct nodes connected in one direction             |
| Inventory        | URLs, documents, sources, content       | Compact rows with status or disposition               |
| Release gate     | Launch checks, approvals, readiness     | Short checklist with clear pass/pending states        |
| Metric snapshot  | Measurement and monitoring              | One dominant signal plus restrained context           |
| Information tree | Navigation, architecture, relationships | Parent node with a small number of branches           |
| Proof stack      | Evidence, trust, requirements           | Visually different evidence layers or cards           |
| Transformation   | Before/after, parsing, migration        | Two states with a clear transformation between them   |
| Abstract system  | Infrastructure or broad capability      | Minimal nodes, orbit, or field with a concrete legend |

## Selection test

For each feature, shortlist three modes and ask:

1. Which makes the claim understandable without reading a paragraph?
2. Which is structurally different from adjacent visuals?
3. Which can use honest labels from the route content?
4. Which survives a narrow mobile crop?

Prefer a simple flow or checklist to a fake dashboard. Use an abstract system only when the subject is genuinely abstract.

## Composition rules

- Give the visual one focal point.
- Limit supporting groups to three or four.
- Use one strong accent and one quiet supporting color.
- Make states differ by label or icon, not color alone.
- Keep decorative layers behind the information.
- For a batch, vary container shape as well as internal content.
