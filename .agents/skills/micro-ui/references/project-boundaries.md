# Project boundaries

## Sources

- Tokens: `src/app/globals.css`
- OG image: `src/app/opengraph-image.tsx`
- Use-case content: `src/content/use-cases/*.json`
- Use-case visual mapping: `src/app/uses/[slug]/_components/feature-visuals.tsx`
- Feature ID validation: `src/lib/use-cases.ts`
- Launch requirements: `docs/launch/checklist.md`

## Placement

- Keep a one-route visual in that route's `_components` folder.
- Promote only after a second real consumer.
- Keep the use-case JSON limited to the single feature ID and content. Component props and layout do not belong in JSON.
- Use the existing `Record<UseCaseFeatureId, ComponentType>` mapping so TypeScript catches missing visuals.
- Keep the default OG implementation generated by Next unless the project explicitly needs uploaded/static social assets.

## Design tokens

Use the current semantic palette rather than copying literal colors from another product:

- canvas/paper for surfaces;
- ink/ink-muted for hierarchy;
- signal for the primary accent;
- mint/mint-strong for completion and supporting emphasis;
- night for dark stages.

Read the actual values before rendering an image because clients may replace every token.

## Verification

Relevant checklist IDs are `BRAND-01`, `SEO-02`, `SOCIAL-01`, `PERF-01`, `A11Y-01`, and `IMAGE-01`. Do not duplicate their requirements here. Verify the rendered asset/page, then place evidence or exceptions in `docs/launch/status.md`.
