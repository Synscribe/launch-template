# Project boundaries

## Sources

- Tokens: `src/app/globals.css`
- OG image: `src/app/opengraph-image.tsx`
- Use-case content: `src/content/use-cases/*.json`
- Use-case visual resolver and source map: `src/app/uses/[slug]/_components/use-case-visual.tsx`
- Use-case React visuals: `src/app/uses/[slug]/_components/use-case-visual-components.tsx`
- Use-case local files: `public/media/uses`
- Visual ID validation: `src/lib/use-cases.ts`
- Launch requirements and status: `docs/launch/checklist.json`
- Generated readable checklist: `docs/launch/checklist.md`

## Placement

- Keep a one-route visual in that route's `_components` folder.
- Promote only after a second real consumer.
- Keep the use-case JSON limited to content and one `visualId` per hero/capability. Component names, file paths, props, and layout do not belong in JSON.
- Add allowed IDs to `USE_CASE_VISUAL_IDS`, then populate the exhaustive `Record<UseCaseVisualId, UseCaseVisualSource>` in `use-case-visual.tsx` so TypeScript catches missing sources.
- Use `kind: "component"` for route-local React, including an isolated interactive Client Component when justified. Put an interactive visual in its own `*.client.tsx` module instead of moving the resolver or shared visual file across the client boundary. Use `kind: "image"` for an approved project-owned file with intentional alt text.
- Prepare local images for the resolver's 4:3 frame and inspect the real crop. Do not depend on an arbitrary source crop.
- Keep the default OG implementation generated by Next unless the project explicitly needs uploaded/static social assets.

## Design tokens

Use the current semantic palette rather than copying literal colors from another product:

- canvas/paper for surfaces;
- ink/ink-muted for hierarchy;
- signal for the primary accent;
- mint/mint-strong for completion and supporting emphasis;
- night for dark stages.

Read the actual values before rendering an image because clients may replace every token.

## Verification

Relevant checklist IDs are `BRAND-01`, `SEO-02`, `SOCIAL-01`, `PERF-01`, `A11Y-01`, and `IMAGE-01`. Do not duplicate their requirements here. Verify the rendered asset or page, then update the matching status in the canonical JSON.
